# P0.3 — API and worker skeletons

## Context
Read first: `CLAUDE.md`, `docs/architecture.md`, `docs/security.md`,
`docs/performance.md`, ADR 0003, ADR 0007, ADR 0009.
What exists already: monorepo (P0.1), local services (P0.2).

## Goal
A running API and worker with all cross-cutting plumbing in place, so feature
modules only add business logic: validated config, health checks, Zod-based
validation and OpenAPI, problem-details errors, request IDs, structured logs
that cannot leak personal data, tracing, security headers, rate limiting, and a
generated typed API client.

## Scope

### `apps/api`
- NestJS with the Fastify adapter, ESM, listening on `API_PORT` (4000).
- **Config module:** all environment variables parsed by one Zod schema at
  startup; invalid config aborts with a clear message. Typed `AppConfig`
  injected everywhere. Includes the deployment flags from
  `docs/hosting-and-billing.md`.
- **Validation:** a global pipe validating `body`, `query`, `params` with Zod
  schemas from `packages/shared`. Route decorator `@Endpoint({ method, path,
  request, response, permission, summary })` that registers the route, its
  schemas and (from P0.7) its permission in one place.
- **OpenAPI 3.1** generated from the Zod schemas
  (`@asteasolutions/zod-to-openapi` or equivalent, MIT); served at
  `/api/v1/openapi.json` in dev; written to `packages/api-client/openapi.json`
  by `pnpm api:openapi`.
- **Errors:** global exception filter → RFC 9457 `application/problem+json`
  with `type`, `title`, `status`, `detail`, `instance`, `requestId`, and
  `errors[]` for validation failures. Error messages never contain personal
  data. Unknown errors → 500 with a generic message, full details only in logs
  (redacted).
- **Request ID:** accept `X-Request-Id` from Caddy if valid, otherwise
  generate (UUIDv7); returned in responses and attached to logs and traces.
- **Logging:** pino, JSON. Redaction list in `packages/shared/src/logging/redact.ts`
  (keys such as `email`, `phone`, `name`, `givenName`, `familyName`,
  `personalIdentityNumber`, `address`, `message`, `body`, `authorization`,
  `cookie`, `token`). Request bodies and query strings are **never** logged.
  Unit test: logging an object containing those keys produces `[redacted]`.
- **OpenTelemetry:** traces and metrics via OTLP when `OTEL_EXPORTER_OTLP_ENDPOINT`
  is set; HTTP, Postgres and Valkey auto-instrumentation; span attributes never
  include personal data.
- **Security:** `@fastify/helmet` (strict defaults; API sets no CSP for JSON
  but sets `X-Content-Type-Options`, `Referrer-Policy`, etc.), CORS limited to
  configured origins, body size limit (1 MB default, uploads go direct to object
  storage later), request timeout, `@fastify/rate-limit` backed by Valkey with
  per-IP defaults and a decorator for per-route limits.
- **Health:** `GET /health/live` (process up), `GET /health/ready` (Postgres
  and Valkey reachable, migrations up to date — the migration check is stubbed
  until P0.4).
- **AGPL meta endpoints:** `GET /api/v1/meta/version` (version, git commit) and
  `GET /api/v1/meta/source` (URL of the exact source, from `SOURCE_URL` +
  commit).
- **Module boundaries:** dependency-cruiser (MIT) rules: a module may import
  only another module's `index.ts` (its public service), never its internals;
  `packages/*` never import from `apps/*`. Runs in `pnpm lint`.
- Graceful shutdown (drain connections, close pools).

### `apps/worker`
- Separate process sharing config, logging and tracing setup with the API
  (put shared bootstrap code in `packages/shared` or a new
  `packages/server-kit`).
- Graphile Worker connected to Postgres, with a `noop` job and a cron-style
  `heartbeat` task, proving scheduling works. Job handlers follow the same
  logging/redaction rules.

### `packages/api-client`
- Generated types from `openapi.json` (`openapi-typescript`, MIT) and a thin
  typed fetch client (`openapi-fetch`, MIT) that adds request IDs and maps
  problem-details responses to a typed `ApiError`.
- `pnpm api:client` regenerates; CI fails if the committed client is out of date.

## Privacy and security
- The redaction test is mandatory and runs in CI.
- No stack traces in HTTP responses outside `NODE_ENV=development`.

## Protected identity
n/a yet; the `@Endpoint` response schemas will later be checked so person
objects only come from the visibility presenter (P0.7).

## Locale and country packs
Problem-details `title` uses message keys resolved from `Accept-Language`
(sv, en); full i18n arrives in P0.9.

## Performance
- `GET /health/live` p95 < 5 ms locally.
- Benchmark script (`autocannon`, MIT) for a trivial endpoint, to keep
  framework overhead visible.

## Seed data
n/a.

## Acceptance criteria
- [ ] `pnpm dev` starts API and worker; `/health/ready` is green against the compose services.
- [ ] Invalid env var → API refuses to start, naming the variable.
- [ ] Invalid request → 400 problem details with field errors; test covers it.
- [ ] Unknown error → 500 problem details with `requestId`, no stack trace.
- [ ] Redaction unit test passes; an integration test asserts a request with an email in the body does not put the email in captured logs.
- [ ] OpenAPI document generated and valid; API client regenerates and is committed; CI checks it is current.
- [ ] dependency-cruiser rule violations fail lint (fixture test).
- [ ] Worker runs the heartbeat job every minute in dev.
- [ ] `docs/architecture.md` updated with any naming decisions.

## Out of scope
Database schema and tenancy (P0.4), authentication (P0.6), authorization (P0.7).
