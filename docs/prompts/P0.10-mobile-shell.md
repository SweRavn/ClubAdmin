# P0.10 — Mobile shell (iOS and Android)

## Context
Read first: `CLAUDE.md` (mobile licence rule), `docs/architecture.md`
(Mobile, Authentication), `docs/performance.md` (Mobile), `docs/licensing.md`
(Mobile app stores), ADR 0008, ADR 0012, ADR 0022.
What exists already: API with read endpoints (P0.7), demo data (P0.8), web
shell for reference (P0.9).

## Goal
An Expo app for iOS and Android that logs in securely, shows my clubs, groups
and members with the same visibility rules as the web, works with cached data
when offline, and passes the stricter mobile licence check, ready for app-store
builds later.

## Scope

### Project
- Expo (current SDK) in `apps/mobile`, Expo Router, TypeScript strict,
  workspace-compatible Metro config.
- Uses `packages/api-client`, `packages/shared`, `packages/i18n` catalogues
  (i18next + i18next-icu) — no web-only packages.
- **`pnpm licenses:check --mobile` must pass**: no GPL/LGPL/AGPL in the bundle.
- App identifiers configurable (`APP_ID_SUFFIX` for dev/staging/prod variants).

### Authentication
- Authorization code + PKCE via the system browser (`expo-auth-session` /
  `expo-web-browser`), redirect `clubadmin://auth/callback`, Zitadel `mobile`
  app from P0.6.
- Refresh token in `expo-secure-store` (Keychain/Keystore); access token in
  memory only; refresh rotation; logout revokes.
- Dev builds with DEV_AUTH: persona picker screen (same personas endpoint),
  hidden in release builds (compile-time flag) and refused by the API in
  production anyway.
- Biometric unlock (optional setting) for re-opening the app.

### Screens
- Login, Home (my clubs, my groups, my children's groups), club switcher,
  Group (owners, leaders, members with `ProtectedBadge` equivalent), Person
  profile (filtered), Settings (language, theme, sessions, log out),
  About (version, **Source code** link, licences list generated at build).
- "Viewing as" child switcher, as on the web.

### Data and offline
- TanStack Query persisted to MMKV (`react-native-mmkv`, MIT): cached
  screens render instantly on cold start; background refresh.
- Cache is **per account** and wiped on logout; persisted data excludes
  fields marked sensitive (none in these screens beyond names).
- Network-status banner; read-only offline mode (writes come later with the
  outbox pattern in P1.5).

### Quality
- Unit tests with jest-expo; component tests with React Native Testing Library.
- E2E with Maestro (Apache-2.0) flows: login as persona, switch club, open
  group, protected-identity check (Liam vs Erik), language check (Lars).
- CI: type check, tests, licence check, Android debug build
  (`expo prebuild` + Gradle) on Linux runners; iOS build job on macOS runner
  optional/manual.
- Accessibility: dynamic type, screen-reader labels, sufficient contrast.

## Privacy and security
- No tokens in AsyncStorage/MMKV; screenshots allowed but the app sets
  `FLAG_SECURE` on Android for screens showing protected persons to
  privileged viewers.
- Deep links validated; only `clubadmin://` and universal links for the
  configured domain.

## Protected identity
Same visibility as web (it comes from the API); `ProtectedBadge` with the
crossed-camera icon and accessible label.

## Locale and country packs
Device locale used before login; after login, user preference → club default.

## Performance
- Cold start to cached Home < 2 s on a mid-range Android device (measured in
  a release build on an emulator profile; documented).
- JS bundle size tracked in CI.

## Seed data
Uses P0.8 personas.

## Acceptance criteria
- [ ] Log in (PKCE against local Zitadel via Caddy, and DEV_AUTH in dev builds) on iOS simulator and Android emulator.
- [ ] Home, group and profile screens show the same people as the web for the same persona.
- [ ] App opens with cached data in airplane mode after a previous session.
- [ ] Logout wipes tokens and cache.
- [ ] `licenses:check --mobile` passes; About lists all third-party licences.
- [ ] Maestro flows pass in CI (Android).
- [ ] `docs/development.md` has mobile setup instructions.

## Out of scope
Push notifications (P1.7), app-store submission, writes/offline outbox,
streaming.
