# P0.8 — Seed framework and demo scenario

## Context
Read first: `CLAUDE.md`, **`docs/seed-data.md` (authoritative)**,
`docs/domain-model.md`.
What exists already: core domain services (P0.5), authentication with
`DEV_AUTH` (P0.6), authorization and visibility (P0.7).

## Goal
`pnpm db:reset` produces the three demo clubs and all named personas from
`docs/seed-data.md` in seconds, deterministically, so that development and
manual testing in the web app can start immediately with realistic
multi-role, multi-club and family situations.

## Scope

### Framework (`packages/db/seed/`)
- Scenario runner: `pnpm db:seed [--scenario demo|minimal|load] [--size n]`.
- `pnpm db:reset`: drop and recreate the dev database, bootstrap roles,
  migrate, seed `demo`. Refuses unless `NODE_ENV=development` and the database
  host is local or explicitly allowed (`SEED_ALLOW_HOST`).
- **Writes through the domain services** with the persona as actor
  (`withActor`/`withTenant`), not raw inserts, so invariants, audit events
  and record history are produced exactly as in real use. Exception: bulk
  generation in the `load` scenario may use a fast path, documented.
- Deterministic: fixed UUIDs for clubs, groups and named personas
  (`packages/db/seed/ids.ts`, exported for tests); Faker with a fixed seed for
  generated people; all dates relative to "today" (birth dates computed so ages
  in the table stay correct).
- **Time travel for history:** the runner can set the transaction timestamp
  context so replayed changes ("Anna ended Peter's manager role last year")
  appear with past `changed_at` values. Implemented via a seed-only setting
  read by the history trigger **only** when `app.seed_time` is set and the
  database has the `seed_mode` flag (never in production).
- Per-module seed steps: `packages/db/seed/steps/<module>.ts`, registered in
  order; later modules (activities, chat…) add steps without touching existing
  ones.
- Reserved test data only: `.test` email domain, test phone ranges, official
  test personal identity numbers (SE: Skatteverket testpersonnummer; NO:
  synthetic test numbers). A unit test asserts every seeded email ends in
  `.test`.

### Demo scenario content (this package)
- Clubs, settings (country, locale, time zone, `join_policy`), managers and
  hand-over states.
- Groups with kinds, hierarchy, owners (including a group with none),
  capacities and `admission_mode`.
- All named personas 1–25 with accounts (or none), guardianships (incl.
  pending co-guardian invitation, relative with view-only rights, divorced
  parents in separate households), club memberships (active, applied, left,
  scheduled for anonymisation), group memberships and functions, club roles
  (current and historic), employments, protected-identity flags (global and
  club-level).
- Waiting list entries for SVK F2017 and IKN F2015 as described (schema from
  P0.5; offers as plain data — behaviour comes in P1.10).
- Generated extra members to fill groups to the listed sizes.
- Historic changes replayed for the History panel (list in `seed-data.md`).
- Platform operator persona with a support-access grant to IKN.
- Data for later modules (activities, chat, calendar feeds…) is **not** part
  of this package; each later prompt adds its own step.

### `minimal` and `load` scenarios
- `minimal`: one club, one group, three people (manager, member, child with
  guardian) for fast tests.
- `load`: parameterised generator (`--size` clubs; default 1,000 clubs /
  200,000 people) using the same builders; used by performance tests from P0.7
  onwards. Must finish in under 10 minutes for the default size.

### Persona picker data
- `GET /api/v1/dev/personas` (from P0.6) returns personas with a short
  description and tags (e.g. "board + parent in two clubs",
  "protected identity") taken from `packages/db/seed/personas.ts`, so the
  picker is self-explanatory.

## Privacy and security
- Seed refuses to run against hosted/production configuration (tests).
- No real-looking personal identity numbers outside official test ranges.

## Protected identity
Nadia, Samira and the club-flagged SVK senior player are seeded with flags;
an integration test logs in as different personas and asserts who can see
them (reuses P0.7 tests with real seed data).

## Locale and country packs
FIL uses the NO pack (nb-NO, Europe/Oslo); Lars has `nb` preference; Liam has
`en` preference.

## Performance
- `pnpm db:reset` with demo scenario: < 15 s.
- `load` default: < 10 min, then the P0.7 budgets are measured against it in
  the nightly job.

## Acceptance criteria
- [ ] `pnpm db:reset` creates exactly the clubs, groups and personas in `docs/seed-data.md` (snapshot test of a structured summary, not raw rows).
- [ ] Running the seed twice gives identical IDs and identical summaries.
- [ ] Every persona's relationships match the table (generated assertions per persona).
- [ ] History contains the replayed changes with the right actors and past timestamps.
- [ ] Persona list endpoint returns all personas with descriptions.
- [ ] Seed refuses to run with `NODE_ENV=production` or `DEPLOYMENT_MODE=hosted`.
- [ ] `load --size 10` runs in CI; full size in the nightly job.
- [ ] `docs/seed-data.md` updated where implementation details differ.

## Out of scope
UI (P0.9), seed data for modules not yet built.
