# P0.4 — Database foundation

## Context
Read first: `CLAUDE.md` (rules 1, 3, 13), `docs/architecture.md`
(Multi-tenancy), `docs/security.md` (Audit), ADR 0004, ADR 0009, ADR 0017.
What exists already: API and worker skeletons (P0.3), Postgres 18 in compose
(P0.2).

## Goal
Every later table gets tenant isolation, record history and audit with almost
no effort, and it is impossible to forget them without CI failing. Tests run
fast against a real Postgres.

## Scope

### `packages/db`
- Drizzle ORM + `pg` driver. Schema files per module under
  `packages/db/src/schema/<module>.ts`.
- **Migrations:** drizzle-kit generates SQL migrations; hand-written SQL
  migrations (RLS, triggers, functions) live in the same sequence. One runner
  (`pnpm db:migrate`) applies them as `clubadmin_owner` inside a transaction
  each, records them in a migrations table, and refuses to run if a migration
  file already applied has changed (checksum).
- Primary keys default to Postgres 18 `uuidv7()`.
- Common columns helper: `id`, `created_at`, `updated_at` (trigger keeps it
  current), and for club tables `club_id` (FK to `clubs` from P0.5; the FK is
  added there).

### Database roles (`packages/db/sql/roles.sql`, run by `pnpm db:bootstrap`)
| Role | Purpose |
|---|---|
| `clubadmin_owner` | Owns schemas and tables; runs migrations; not used by the app |
| `clubadmin_app` | Used by API and worker; `NOBYPASSRLS`; DML only on app schemas; `INSERT` only on history/audit (via functions) |
| `clubadmin_operator` | Audited operator tooling; must set an operator actor |
| `clubadmin_retention` | Retention/erasure jobs: may delete/scrub history and audit rows |
`pnpm db:bootstrap` is idempotent and also used by self-hosters.

### Request context and tenancy
- `withTenant(ctx, fn)`: opens a transaction on the `clubadmin_app` pool and
  sets transaction-local settings with `set_config(..., true)`:
  `app.club_id`, `app.person_id`, `app.on_behalf_of`, `app.request_id`,
  `app.actor_kind`. `fn` receives a typed transaction handle.
- `withActor(ctx, fn)`: same, without a club (for global tables such as
  `people`, `accounts`).
- `withSystem(jobName, { clubId? }, fn)`: for worker jobs; `actor_kind =
  system_job`.
- SQL helper functions `app.current_club_id()`, `app.current_person_id()`
  (return NULL when unset; never error).
- Migration helper `enableTenantRls('table')`: `ENABLE` + `FORCE ROW LEVEL
  SECURITY`, policy `club_id = app.current_club_id()` for all commands.
  Global tables get explicit policies in their own migrations.
- Repositories cannot reach the raw pool: the only exported entry points are
  `withTenant`/`withActor`/`withSystem` (enforced by dependency-cruiser).
- Compatible with PgBouncer transaction pooling (no session-level `SET`).

### Record history (ADR 0017)
- Schema `history`, table `record_changes` **partitioned by month** on
  `changed_at`, columns as in ADR 0017. Indexes:
  `(table_name, record_id, changed_at desc)` and `(club_id, changed_at desc)`.
- Trigger function `history.capture()` (`SECURITY DEFINER`, owned by
  `clubadmin_owner`): for UPDATE stores only changed columns (old/new JSONB);
  for INSERT/DELETE the full row; reads actor settings; falls back to
  `actor_kind = 'db_role'` + `current_user` when unset.
  (P0.8 adds a seed-only timestamp override, guarded so it can never apply in
  production.)
- `enableHistory('table', { skipInsert?, redact?: string[] })` migration helper.
  Redacted columns are stored as `"[changed]"`.
- Worker job `history.maintainPartitions`: creates partitions 3 months ahead,
  drops expired ones per retention setting (default 24 months).
- Read API in the db package: `getRecordHistory(tx, table, recordId, { cursor })`
  (keyset pagination) — the HTTP endpoint and UI come in P1.9.

### Audit events
- `audit.events` (append-only): `id`, `club_id`, `actor_person_id`,
  `on_behalf_of_person_id`, `action` (dotted name, e.g. `group.owner.added`),
  `resource_type`, `resource_id`, `changed_fields` (names only),
  `ip_hash`, `request_id`, `created_at`. RLS by club; app role insert-only.
- `audit.record(tx, event)` helper; typed action names registered in
  `packages/shared`.

### Outbox and domain events
- `outbox.events` table written in the same transaction as the change;
  worker task dispatches to handlers with at-least-once delivery and an
  idempotency key; failed handlers retry with backoff and alert after N tries.
- Typed `DomainEvent` registry in `packages/shared`.

### Deletion ledger
- `privacy.deletion_ledger` (person IDs erased, timestamp, reason) used by the
  restore procedure (P0.11) and erasure jobs (P1.8). Outside the scope of
  per-club exports.

### CI guards (integration tests)
- Every table with a `club_id` column has RLS enabled and forced.
- Every table in app schemas has the history trigger, unless listed in
  `packages/db/history-exclusions.ts` with a reason (initially: outbox,
  Graphile Worker tables, history itself, migrations table).
- `clubadmin_app` has no `BYPASSRLS`, no DDL, no UPDATE/DELETE on history/audit.
- A migration that drops or renames a column without the expand/contract
  pattern is flagged (simple lint on migration SQL; warn, can be overridden
  with a comment and reason).

### Test harness
- Integration tests run against Postgres from compose (or a CI service
  container). A template database is migrated once per run; each test file gets
  a fresh clone (`CREATE DATABASE … TEMPLATE …`) for isolation and speed.
- Helpers: `createTestClubs(2)`, `asPerson(personId, clubId)`, and
  `expectTenantIsolation(fn)` which runs `fn` as a person of club B against
  club A's data and asserts zero rows / 404.

## Privacy and security
- History stores ciphertext or redaction markers for sensitive fields, never
  plaintext of encrypted columns.
- Only `clubadmin_retention` can delete history/audit rows.

## Protected identity
History/audit actor IDs are resolved to names only in presenters (P0.7), so
protected actors can be masked.

## Performance
- `withTenant` overhead (transaction + settings) < 1 ms per request locally.
- History trigger overhead measured on a 10,000-row update benchmark and
  documented in `docs/performance.md`.
- Integration test suite startup (template clone) < 1 s per file.

## Acceptance criteria
- [ ] `pnpm db:bootstrap && pnpm db:migrate` works on a fresh database and is idempotent.
- [ ] A sample club table: rows of club A invisible under club B's context, also for UPDATE/DELETE; test passes.
- [ ] Updating one column writes one history row with only that column, correct actor, request id and on-behalf-of.
- [ ] A change made with no context is recorded with `actor_kind = db_role`.
- [ ] App role cannot UPDATE/DELETE history or audit rows (test).
- [ ] CI guards fail when a fixture table lacks RLS or history.
- [ ] Outbox: an event written in a rolled-back transaction is never dispatched; a committed one is dispatched once even if the worker restarts mid-way.
- [ ] Partition maintenance job creates future partitions.
- [ ] `docs/architecture.md` updated with the final helper names.

## Out of scope
Domain tables (P0.5), HTTP endpoints for history (P1.9), backups (P0.11).
