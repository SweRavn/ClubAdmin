# P2.7c — Fixes from testing: car pools in the answer, form errors, places, club menu, administration

To do after P2.7b and before P2.8. Findings from the maintainer's testing
of the web app with the demo data on 2026-11-19.

## Context
Read first: `CLAUDE.md`, `docs/seed-data.md`, ADR 0055 (updates in place,
one tap for a single choice), ADR 0048 (car pools, amended in P2.7b: open
unless the transport mode is `shared`), ADR 0035 (answers), ADR 0046
(roles), ADR 0022 (person visibility).

What exists already (checked against the code on 2026-11-19):
- Car pools: `apps/api/src/modules/carpools` (offers per direction;
  `withReturn` creates the return offer with the outward offer's
  `departurePlace` and `departureAt`; bookings for oneself or a ward, the
  return seat with `alsoReturn`; `canBookFor` is only those on the roster
  and the caller's wards; the driver cannot book their own car), the web
  section `apps/web/src/components/carpool.tsx` (the booking form only on
  another person's car with free seats), the mobile screen.
- Answers: `ResponseForm` (web, two submit buttons and a note) and the
  mobile `ResponseButtons`; "Mitt schema" (`/schedule`) and a group's
  activity list show the answer buttons.
- Form errors: the BFF action route (`apps/web/src/app/actions/[action]/route.ts`)
  turns a failed call into `?error=<code>`; a form that `actions.ts` cannot
  map, or the API's `validation` problem, becomes `invalid_input`, shown
  as "Kontrollera formuläret". The API's validation problem already
  carries `errors` (the issues with their paths), which the route ignores.
- Places: `clubs/:clubId/locations` (create with `club.locations.create`,
  change, archive and restore with `club.locations.manage`); no delete.
- The club menu (`ClubSwitcher`, `app-frame.tsx`): on personal pages
  (`/`, `/schedule`, `/me…`) it shows "Alla föreningar", but the main
  navigation still lists the last club's items, and the menu has no entry
  to go back to "Alla föreningar" once a club is chosen.
- Roles are given on a person's page (`/people/:id`, section roles) and
  read on `/clubs/:clubId/roles`; the navigation has no entry for roles,
  administrators, settings and the other club administration pages, which
  are reached from links on the club page.
- The chat room (`chat-room.tsx`) grows with its messages
  (`min-h-[60vh]`, no maximum).

## Goal
Each finding is fixed, with a test that would have caught it.

## Findings and what to do

0. **The chat's "Ej ansluten" stayed (done 2026-11-19, before this prompt).**
   The web chat now connects on the page's own host (`/api/v1/realtime`,
   forwarded by Caddy), the banner says the technical reason, and
   `pnpm dev:services` reloads the Caddyfile (Caddy kept the old
   configuration, so the WebSocket ended with 1006). Check it stays fixed:
   the chat e2e test asserts the host and the banner.

1. **Places cannot be removed.** A place nobody uses (no activity, series,
   event or programme refers to it) can be deleted
   (`DELETE /clubs/:clubId/locations/:locationId`, `club.locations.manage`,
   or `club.locations.create` for one's own unused place; audit and
   history); a place in use is archived instead, and the page says so
   ("Används av 12 aktiviteter – arkiveras i stället"). The web page shows
   "Ta bort" or "Arkivera" accordingly, both with a confirmation.
   Integration test for both paths, matrix row, budget.

2. **Creating an event only says "Kontrollera formuläret".** The user must
   see what is wrong, next to the field:
   - The BFF route passes the API's validation `errors` on to the page
     (field paths and codes, never values: `?error=invalid_input&fields=title:too_small,endsAt:...`
     or the enhanced JSON answer), and `actions.ts` returns field codes
     for what it checks itself (`eventFieldsOf`, `activityFieldsOf`, ...).
   - `FormError` and the form fields show a translated message per field
     (`aria-invalid`, `aria-describedby`, focus moves to the first field
     in error; the summary at the top lists the fields as links).
   - Start with the event form, then every form built on `ActionForm` that
     can return `invalid_input` (a test lists the actions and fails for one
     without field messages).
   - Playwright: an event with an end before its start, and one without a
     title, show the field's message and keep what was typed.

3. **The return trip of an offered ride gets the outward trip's place and
   time.** Offering "with the return trip" asks for the return's own
   departure place and time (prefilled with the activity's place and its
   end; empty is allowed), in the web and mobile offer forms; the API takes
   `returnDeparturePlace` and `returnDepartureAt` (default: the place of
   the activity and nothing), never copies the outward values. Fix the
   demo data if it relies on the copy. Integration test.

4. **No way to sign up for a ride.** Find why the maintainer could not
   book a seat (as Erik in F2017: probably only his own car, or he is a
   leader not counted as a passenger, or the activity's car pool shows no
   form) and fix the cause:
   - Every car with free seats shows "Åk med dit" and "Åk med hem"
     (separate buttons, one tap each, ADR 0055) for each person the viewer
     may book for; with several people a small menu.
   - Where booking is not possible the car says why (your own car, full,
     not taking part, the trip has started).
   - Leaders who take part may book a seat like participants.
   - Demo data: SVK F2017's next training has two other families' cars
     with free seats there and home, so Erik and Sara can book.
   - Playwright and Maestro: book there and home separately, cancel.

5. **Book a ride from "Mitt schema" and a group's activity list.** Each
   activity with a car pool shows, next to the answer, "Åk med dit" and
   "Åk med hem" (the seat taken, or the cars with free seats) without
   opening the activity; one tap books, the row updates in place. The
   schedule's request budget stays independent of the data (the car pool
   summary is read for the page's activities in one query).

6. **"Kommer" with how one gets there.** On the web and in the mobile app,
   "Kommer" opens a small menu: "Tar mig dit själv" and the cars with free
   seats for the trip there, each with the driver (person presenter) and
   the pick-up place and time; choosing a car answers "attending" and books
   the seat in one action (one transaction in the API, or the answer and
   the booking with the booking's failure shown and the answer kept). With
   no car pool (shared transport) "Kommer" answers at once as today. The
   choice is changeable later. A protected driver is shown as the
   presenter allows. API: `POST /activities/:id/responses` takes an
   optional `ride: { offerId, alsoReturn }`, or a new endpoint; decide and
   note it in ADR 0048.

7. **The chat window has no maximum size.** The chat room has a maximum
   height (the viewport minus the frame; the message list scrolls inside,
   newest at the bottom, the input stays visible), on desktop and phone;
   long messages wrap. Playwright: 50 messages keep the input in view.

8. **"Alla föreningar" in the club menu.** Make the menu mean what it says:
   - The menu has "Alla föreningar" as its first entry; choosing it goes to
     the personal start page and clears the last chosen club for the
     navigation.
   - With "Alla föreningar" the main navigation shows only the person-wide
     pages (Hem, Mitt schema, Kalender, Chatt, Mina dokument, Mina
     uppgifter, Mina samåkningar, ...), each covering all the person's
     clubs; the club's pages (Grupper, Medlemmar, Evenemang, ...) appear
     when a club is chosen. Check each person-wide page really covers
     every club (list any that do not and fix them or move them to the
     club's navigation).
   - Playwright: choose a club, then "Alla föreningar"; the navigation
     changes accordingly.

9. **Where are roles given? An "Administration" tab.** Karin Ek (club
   manager of IKN) could not find where to give roles. Add one
   "Administration" entry in the club's navigation for holders of any
   administration permission, leading to a page that groups the club's
   administration (each item only for those who hold its permission):
   - Medlemmar: register, applications, invitations, waiting lists,
     duplicates, import;
   - Roller och behörigheter: roles, "who can …?", administrators, and
     **"Ge en roll"**: pick a person (search as you type) and a role, or
     from a role's page add holders with the same search and end their
     role (with the same rules, MFA and audit as on the person's page);
   - Föreningen: settings, profile, places, plugins, grants, billing,
     storage;
   - Integritet och logg: privacy, audit log, history, profile views,
     protected identities, safeguarding.
   - **The role matrix** ("Rollöversikt"): for holders of
     `club.roles.manage` (others with `club.roles.read` see it read-only),
     people in rows and the club's roles in columns (club roles, and group
     roles per group as a second view chosen above the table); a cell shows
     whether the person holds the role and gives or ends it with one tap
     (ADR 0055: in place, the cell's new state at once, rolled back with an
     error next to it if the API refuses; MFA and recent authentication as
     the person's page requires, asked once for the session). Rows are the
     people who hold any role, plus people added by search as you type;
     filter by name and role; keyset paging of rows (50 per page); sticky
     header row and first column; keyboard: arrow keys move between cells,
     Space toggles; every cell has an accessible name ("Karin Ek –
     Kassör: har rollen"). Locked roles (ADR 0046) and the rules of the
     person's page apply (the last holder of a required role cannot be
     removed, `last_holder`; giving oneself a role is recorded as
     self-assignment). People through the person presenter; protected
     people only for those who may see them. The API reads the matrix in a
     bounded number of statements (people page × roles), with a request
     budget.
   The flat navigation loses the entries that move here. Breadcrumbs
   (P2.7b) show Förening › Administration › page. Playwright: Karin gives
   a role to a member from the role's page and ends it, and toggles a cell
   in the role matrix (given, then ended, without a page reload).
