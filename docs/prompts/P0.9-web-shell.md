# P0.9 — Web shell

## Context
Read first: `CLAUDE.md`, `docs/architecture.md` (Web, Locale),
`docs/performance.md` (Web), `docs/security.md` (Application hardening),
`docs/licensing.md` (Source link), ADR 0008, ADR 0022.
What exists already: minimal Next.js app with BFF auth (P0.6), read endpoints
with visibility (P0.7), demo data (P0.8).

## Goal
A fast, accessible web app you can log into as any demo persona, switch
between clubs, browse groups and members, and see protected identity and
locale behaviour working. This is the base every web feature builds on, and the
first thing the maintainer tests.

## Scope

### Foundation
- Next.js App Router, React Server Components by default; client components
  only for interactivity. TanStack Query for client-side data with the
  generated API client (`packages/api-client`).
- Styling: Tailwind CSS (MIT) with design tokens (colour, spacing, type) in
  `packages/ui`, light and dark themes, accessible primitives built on Radix
  UI (MIT). Add both to `docs/licensing.md`.
- Strict CSP with per-request nonces (middleware), `frame-ancestors 'none'`,
  no inline scripts, Trusted Types where supported.
- Error boundaries, loading skeletons, empty states, 404/403 pages
  (problem-details aware).

### i18n and locale
- Message catalogues in `packages/i18n/messages/{sv,en,nb}.json` (ICU).
  Web uses `next-intl` (MIT; add to licensing table) reading those catalogues.
- Locale resolution: user preference → current club's `default_locale` →
  `Accept-Language` → `en`. Time zone: user preference → club → browser.
- Formatting helpers for dates/times in the club's time zone, showing the
  viewer's zone when different.
- CI check: every key exists in `sv` and `en` (`nb` may fall back to `en`
  with a warning); no string literals in JSX (ESLint rule, e.g.
  `eslint-plugin-i18next`'s no-literal-string or a local rule).

### Layout and navigation
- App frame: top bar with **club switcher** (from `/me/clubs`, remembers last
  club per user), user menu (profile, language, sessions, log out), main nav
  (Home, Groups, Members — Members only if permitted), footer with
  **"Source code"** link (`/api/v1/meta/source`) and version.
- Acting on behalf of a child: if the user has wards, a "Viewing as" switcher
  that sets `X-On-Behalf-Of` for API calls (via the BFF), clearly shown.

### Pages
- `/login`: persona picker when DEV_AUTH (grouped by club, with the persona
  descriptions/tags from P0.8, an MFA toggle), plus "Log in with email".
- `/` (Home): my clubs and my groups (and my children's groups), with role
  badges.
- `/clubs/[clubId]`: club overview (name, logo, managers, groups).
- `/clubs/[clubId]/groups`: groups tree (hierarchy), kind labels.
- `/groups/[groupId]`: group detail with owners, leaders and members, using
  `PersonSummary` only. Protected members show the **crossed-camera icon**
  (`<ProtectedBadge />`, with tooltip "Protected identity — do not photograph,
  film or share") for viewers allowed to see them; others simply don't see
  them.
- `/people/[personId]`: profile with fields filtered by the API.
- `/me/sessions`: list and revoke sessions.
- Onboarding placeholder for people without clubs (Emma): "Find a club" /
  "Create a club" buttons linking to P1.1 pages (disabled with explanation).

### Shared components (`packages/ui`)
`PersonName`, `ProtectedBadge`, `RoleBadge`, `ClubSwitcher`, `DataList`
(keyset pagination, virtualised for long lists), `DateTime`, `EmptyState`.

## Privacy and security
- No personal data in URLs beyond IDs; no analytics scripts.
- `PersonName` only accepts `PersonSummary` (type-level guard), so pages
  cannot bypass visibility.

## Protected identity
Playwright tests: as Liam (member) → IKN F2015 page does not show Nadia; as
Erik (coach there) → Nadia shown with icon; as Samira (guardian) → Nadia shown;
as Emma → 404 on the group URL.

## Locale and country packs
Playwright: Lars sees Norwegian (his preference) even in SVK; Liam sees English;
Anna sees Swedish; FIL pages show Europe/Oslo times.

## Performance
- Lighthouse CI on `/`, `/groups/[id]`: LCP < 1.5 s (cached) on the mobile
  profile, INP < 200 ms, initial JS < 150 KB compressed for member pages
  (`size-limit` or Next.js build stats check in CI).
- Server components fetch in parallel; no client-side waterfalls on first load.

## Seed data
Uses P0.8 personas; no new data.

## Acceptance criteria
- [ ] Log in as any persona via the picker; switch clubs; browse groups and members.
- [ ] Protected-identity and locale Playwright tests above pass.
- [ ] Cross-club URL access shows a 404 page.
- [ ] Guardian "viewing as" switcher works for Anna (Elsa, Oskar).
- [ ] CSP has no `unsafe-inline`; security headers verified in an e2e test.
- [ ] Lighthouse and bundle-size budgets enforced in CI.
- [ ] Keyboard navigation and screen-reader labels on all pages (axe check in Playwright, no serious violations).
- [ ] `docs/licensing.md` updated with new dependencies.

## Out of scope
