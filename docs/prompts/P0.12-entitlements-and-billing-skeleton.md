# P0.12 — Entitlements service and optional billing skeleton

## Context
Read first: `CLAUDE.md` (rule 11), **`docs/hosting-and-billing.md`
(authoritative)**, ADR 0013.
What exists already: authorization engine (P0.7), demo data (P0.8).

## Goal
Features can ask "is this club allowed to use X, and how much?" through one
service that works identically whether billing is off (self-hosted) or on
(hosted). The billing module exists as a skeleton that is only loaded when
enabled, so P1.13 can fill it in without touching feature code.

## Scope

### Entitlements (always present, `apps/api/src/modules/entitlements`)
- Catalogue in `packages/shared/src/entitlements.ts`: feature keys
  (e.g. `chat`, `calendar_feeds`, `streaming`, `documents`, `finance`,
  `sponsors`) and limits (`members_max`, `storage_gb`, `streaming_hours`),
  each with a default for "billing off".
- `EntitlementsService.has(clubId, feature)`, `.limit(clubId, key)`,
  `.snapshot(clubId)`; cached per club with invalidation on subscription or
  flag changes.
- Two providers chosen at startup:
  - `FlagsEntitlements` (`BILLING_ENABLED=false`): everything enabled by
    `FEATURE_*` flags is granted, limits unlimited.
  - `PlanEntitlements` (`BILLING_ENABLED=true`): from the club's subscription
    plan plus add-ons; falls back to a configured default plan.
- `@RequiresEntitlement('streaming')` decorator for endpoints → 402/403
  problem detail `entitlement_required` (clients show an upgrade or "not
  available" message); disabled features (`FEATURE_x=false`) behave as
  "not found" for routes.
- `GET /api/v1/clubs/:clubId/entitlements` (club members) for clients to adapt
  the UI.

### Club access state
- `clubs.access_state`: `active` | `read_only` | `suspended`. A global guard
  rejects writes for `read_only` clubs with a problem detail; reads and
  **exports always work**. Never deletes data. With billing off, only
  operators can change the state.

### Billing skeleton (`apps/api/src/modules/billing`, loaded only if enabled)
- Tables (migrated always, so schemas are stable; empty when unused):
  `billing.plans`, `billing.plan_entitlements`, `billing.subscriptions`,
  `billing.invoices`, `billing.invoice_lines`. RLS: club managers and
  treasurers read their own club's subscription and invoices; operators read
  all billing data (but no member data).
- Services: assign plan to club (operator), start trial (on club creation when
  hosted), subscription status transitions (`trial` → `active` →
  `past_due` → `read_only` → `cancelled`) with domain events that the
  entitlements cache listens to.
- `PaymentProvider` interface (no implementation yet), `InvoiceGenerator`
  interface; the worker has a placeholder monthly job behind the flag.
- Operator endpoints: list plans, assign plan, change subscription status.

### Configuration
- `.env.example`: `BILLING_ENABLED`, `BILLING_DEFAULT_PLAN`,
  `BILLING_TRIAL_DAYS`, `FEATURE_*`.

### Tests
- The whole API integration suite runs twice in CI: `BILLING_ENABLED=false`
  and `true` (matrix).

## Privacy and security
- Billing data is organisation data; no member personal data in billing
  tables (CI guard: no person-referencing columns besides the club's contact
  manager ID).
- Operator billing actions are audited.

## Protected identity
n/a (no person listings).

## Locale and country packs
Plans have prices per currency; amounts stored as integer minor units with
currency code.

## Performance
`EntitlementsService.has` < 0.1 ms with warm cache; no DB query per request.

## Seed data
Demo: SVK on a paid plan (active), IKN on the free plan, FIL in a trial ending
in 10 days — created only when `BILLING_ENABLED=true`; with billing off the
seed skips billing data.

## Acceptance criteria
- [ ] With billing off: no billing routes registered, all enabled features granted, suite green.
- [ ] With billing on: plan determines entitlements; changing plan takes effect on the next request.
- [ ] `read_only` club: writes rejected, reads and export allowed (test).
- [ ] `@RequiresEntitlement` blocks a sample endpoint when not entitled.
- [ ] CI matrix runs both modes.
- [ ] `docs/hosting-and-billing.md` updated with final names.

## Out of scope
Payment provider integration, invoice PDFs, pricing UI, dunning emails (P1.13).
