# P2.7b — Web fixes from testing (navigation, search, forms, demo data)

To do after P2.7 is complete. Findings from manual testing of the web app
with the demo data on 2026-11-19.

## Context
Read first: `CLAUDE.md`, `docs/seed-data.md`, ADR 0022 (person visibility),
ADR 0046 (roles and permissions).
What exists already: the app frame (`apps/web/src/components/app-frame.tsx`:
main navigation, the "Viewing as" menu from `/me/wards`), the roles pages
(`apps/web/src/app/(app)/clubs/[clubId]/roles/`, "Who can …?" in
`roles/holders`), the role name schema (`RoleTextsSchema` in
`packages/shared`: `sv`, `en`, `nb`), the event form
(`apps/web/src/components/event-fields.tsx`, `RowList`).

## Goal
The problems seen in testing are fixed, each with a test that would have
caught it.

## Findings and what to do

1. **"Viewing as" shows Elsa twice (logged in as Mikael Lindqvist).** The
   second entry is a different person: `elsa-duplicate` in
   `docs/demodata/relationships.json`, the deliberate duplicate for the
   merge-duplicates demo, with the same name. Two people with the same name
   cannot be told apart in the menu. Do:
   - When two or more entries in the menu have the same label, add what
     tells them apart and the viewer may see (for a guardian: the birth
     year; otherwise the club), through `personLabel`/the presenter's data,
     never new name fields.
   - Check `/me/wards` and the menu never list the same person twice (one
     entry per person even with several guardianships); a test for both.
   - Consider also showing the duplicate hint ("possible duplicate") to
     guardians where the person is already flagged as a possible duplicate; if that needs
     a design decision, note it in the PR instead.

2. **The main navigation overflows (logged in as Anna Lindqvist).** With
   many items (Styrdokument, Ansökningar, Köer, Inbjudningar, Kalender,
   Platser, Medlemmar, …) the row runs off the screen. The navigation wraps
   onto more lines when the items do not fit (desktop), keeps the mobile
   menu as it is, and keeps the current item visible. Playwright check at
   1280 px and 1024 px widths with Anna: no horizontal page scroll, every
   item visible.

3. **"Who can …?" is not sorted.** The permission list is sorted
   alphabetically by its label in the viewer's language
   (`Intl.Collator(locale)`), not by key. Unit test for the order in sv
   and en.

4. **Role names in every language.** Creating a role asks for a name in
   Swedish, English and Norwegian. Only the club's language and English are
   required (sv + en for a Swedish club, nb + en for a Norwegian one); the
   other languages are optional, behind "More languages", and can be set
   later when editing the role. A role without a name in a language shows,
   in that language, the club's language name, else the English one
   (fallback at display time; nothing copied into the stored names, so a
   name added later simply takes over). API: unchanged schema (`nb` etc.
   already optional); the create/update endpoints refuse a role without a
   name in the club's language or English (problem detail, i18n). Tests:
   create with sv + en only, display in nb falls back, later edit adds nb.

5. **Creating an event fails (Anna, "Nytt evenemang").**
   - Console error: `Each child in a list should have a unique "key"
     prop` from `RowList` with rows from `EventFields` (`questionRow`,
     `event-fields.tsx` around line 134 and 307). Give each row a key (its
     index or field name), and check the other `RowList` users the same way.
   - The form answered "Kontrollera formuläret" for: whole club, name,
     price text, description, start date and time, **an end time without an
     end date**, a place. Find which field failed and make the error show
     next to that field. An end time without an end date means the start
     date (the hint "Tomt: slutar vid dagens slut" only covers both empty);
     an end before the start is a field error on the end.
   - Playwright test: Anna creates this event with an end time only, and
     with a question row added; no console errors.

6. **Leaving a page with unsaved changes.** Leaving a form with changes
   (navigating away, closing the tab) asks first ("Du har ändringar som
   inte sparats"; the browser's own prompt on unload, an in-app dialog for
   links inside the app). Forms opt in through one shared mechanism (a hook
   or form wrapper in `packages/ui` or `apps/web/src/components`), used by
   at least the event, activity, series, announcement, duty shift and role
   forms. Better still for new events: an unfinished new event is kept as a
   draft when the user leaves, and "Nytt evenemang" offers to continue it.
   Decide where drafts live: in the browser (per device, no server state)
   or as a server-side draft (`status = 'draft'` on the event, visible to
   its creator only, history and audit as for events). If server-side
   drafts need a migration or ADR, write the ADR and keep this prompt's
   change to the browser draft; say which in the PR. Playwright: Anna fills
   in part of a new event, clicks another menu item, gets the question;
   stays; leaves; comes back and continues the draft.

7. **Search as you type.** Finding people to add as group members or owners
   (and every similar person search in the web app: invitations, guardians,
   role holders, duty assignments, merge duplicates, chat members, …)
   searches while the user types (debounced, about 250 ms, from two
   characters), without a "Sök" button. When the matches are fewer than 10
   they are shown as a pop-up list right under the field to pick from with
   the mouse or the keyboard (an accessible combobox: arrow keys, Enter,
   Escape, `aria-activedescendant`); with more, the list says to type more.
   One shared component for all of them. The search endpoints must stay
   within their request budgets per keystroke (keyset-limited, prefix
   indexes as today); cancel the previous request when a new one starts. No
   names in logs or URLs that are logged. Protected people: as today
   (PersonVisibility decides who appears). Playwright: Erik adds a member
   by typing part of a name and picking from the list.

8. **Rename "Ändra grupp".** The button becomes "Gruppinställningar"
   ("Group settings", nb "Gruppeinnstillinger"); the page heading follows.

9. **Breadcrumbs everywhere.** Every page under a club or a group shows a
   breadcrumb trail (Förening › Grupp › Sida, with the club and group names
   and links), as some group pages (duties) already do. One shared component
   driven by the route, so new pages get it; pages missing it today include
   the consents page ("Samtycken"). On mobile widths it collapses to the
   parent link ("‹ F2017"). Accessible (`nav` with `aria-label`,
   `aria-current="page"`). Playwright: the trail on the consents page and on
   a group's attendance page.

10. **Erik cannot create duty shifts in SVK F2017.** Erik is F2017's head
    coach and holds `group.duties.manage`, but SVK has no duty types (the
    demo data only gives IK Norrbacka a catalogue), and the group's duties
    page then hides the "new shift" form without saying why. Do:
    - When the club has no duty types, the group's duties page says so and
      who can add them ("Föreningen har inga typer av arbetspass än. En
      administratör lägger till dem under Arbetspass."), with a link for
      those who hold `club.duty_types.manage`.
    - Seed SVK with a duty type or two (for example "Kiosk" and
      "Sekretariat" for volleyball home matches), so the demo shows a coach
      creating shifts. Update `docs/seed-data.md`.

11. **A waiting applicant the club gives a place cannot answer the offer
    in the demo.** The generated applicants on the demo waiting lists
    (Wilma Forsberg in SVK F2017 and others) are created with a generated
    parent, but without a guardianship between them and without a login, so
    no one can accept the offer. Viktor (Henrik's son) is the applicant who
    can be tested today. Do: link each generated applicant to their
    generated parent (`recordGuardian` as in the seed's other families) and
    give one SVK F2017 applicant's parent a login (a persona-picker entry
    "förälder i kö"), so offering a place and accepting it can be tried end
    to end; document it in `docs/seed-data.md` (waiting lists).

12. **The club's group list does not show the user's own groups.** Split
    the list of the club's groups into "Mina grupper" (groups the viewer,
    or a ward they act for, has a current function in) and "Andra grupper",
    each in the existing order. For a club manager with no groups of their
    own, "Mina grupper" is left out.

13. **Erik sees only part of F2017's waiting list.** Logged in as Erik
    (F2017's head coach and owner), offering a place shows only Viktor and
    Anna Lindqvist (added to the queue while testing); the other waiting
    applicants are missing. Expected: the owner sees every entry in queue
    order (P1.10b). Find the cause (likely: the generated applicants are not
    club members and the presenter or the query leaves out people the
    viewer has no relationship with) and fix it so that a group's waiting
    list shows all its applicants to those who manage the list (protected
    applicants as today: the icon, no name for those without the right).
    Integration test: the owner and the club manager see all five waiting
    in F2017 in the demo scenario.

14. **"Ställ dig i kön" after joining.** When Viktor has accepted his place
    and is a member of F2017, the group still offers "Ställ dig i kön". The
    join and queue actions are hidden for people who already have a current
    function in the group (and for a ward the viewer acts for), and show
    "Du är med i gruppen" instead. Test: after accepting, the button is
    gone (page and API flag, if the page reads one).

15. **The chat says "Ej ansluten" though messages arrive.** In F2017's chat
    (Viktor, Alva) the banner "Ej ansluten – meddelanden visas när
    anslutningen är tillbaka" stays, yet messages are shown and can be
    sent. Find why the real-time connection (the WebSocket gateway, P2.1)
    is not established in development (the URL behind Caddy, the token,
    the origin check, the upgrade through `next dev`) or why the state is
    not updated when it is; fix the connection or the state, and show the
    banner only when it is really down (after a grace period). Playwright:
    open the chat, no banner; stop the connection (route abort), the banner
    appears; restore, it goes.

16. **No emoji in the chat.** Add an emoji picker to the chat's message
    field (web; mobile uses the system keyboard's emoji): a button that
    opens a searchable panel with categories and recently used emoji,
    keyboard accessible, and inserts at the cursor. Use a small dependency
    on the licence allow list (`docs/licensing.md`) or a built-in list;
    keep it out of the initial bundle (load on first open; ADR 0027
    budgets). Reactions (if the chat has them) use the same panel.

17. **The club selector next to "Mitt schema" is confusing.** Erik's "Mitt
    schema" shows all his clubs' sessions, as it should, yet the menu at the
    top shows "Strandvikens Volleybollklubb" selected, as if the schedule
    were that club's. Make clear what the selector means: label it
    ("Förening:" or an icon with a tooltip) and, on pages that are not about
    one club (Mitt schema, Mina köer, Mina uppgifter, notifications, …),
    show "Alla föreningar" (or dim the selector) instead of the last chosen
    club; on club pages it shows the club. Playwright: Erik on Mitt schema
    sees "Alla föreningar"; on a club page, the club.
